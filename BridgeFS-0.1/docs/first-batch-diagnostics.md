# 第一批诊断记录

## Service 偶发卡住

**结论：根因暂未定性，现有证据不足以区分网络阻塞、文件系统等待、锁竞争或系统调度问题。**

仓库和当前会话未提供 ColorOS 的 logcat、ANR trace 或卡住时的运行日志样本。现有应用日志只记录 Service 生命周期、界面切换和指令开始/结果，不记录系统崩溃栈。

代码检查发现，原先的指令执行会在主线程遍历目录、读取文件；运行日志也会在调用线程同步读写。这些路径会让界面等待文件系统。本批已把指令执行与运行日志读写移至单线程后台队列，作为卡顿缓解措施；它不能证明或排除底层文件系统等待，也不代表 Service 偶发卡住已在真机复现并根治。

**已知触发条件：** 尚未记录。建议复现时同时保存卡住前最后一条 BridgeFS 指令、根目录规模、ColorOS/Android 版本、发生时间，以及 logcat 中 ANR / fatal exception 信息。

## ColorOS EditText 触摸崩溃

**结论：目前无法确定是触摸分发还是输入法交互。**

没有崩溃栈或设备复现记录。原悬浮面板的 EditText 点击会打开独立输入弹窗；本批将面板内预览框设为不可直接获取焦点，编辑统一进入独立弹窗，避免悬浮窗 EditText 与系统输入法争抢焦点。这是规避性改动，尚未在 ColorOS 真机确认。

**已知触发条件：** 未知；需要设备型号、ColorOS 版本、输入法名称和崩溃栈才能完成定性。

## 轻微发热

代码搜索未发现定时轮询（例如 `postDelayed`、`TimerTask`、`ScheduledExecutor`）或属性动画（例如 `ValueAnimator`、`ObjectAnimator`）。悬浮球只有拖动和点击响应。Grep 是用户触发的文件扫描，原有扫描有 5 秒上限；目录列举和文件系统访问仍可能在执行期间使用 CPU/存储。本批将指令工作移出主线程，改善响应性，但不会降低扫描本身的工作量。

**结论：** 静态代码未发现持续轮询或动画导致发热；缺少真机温度与耗电对照，不能排除用户触发扫描或 Android/OEM 后台策略的影响。
